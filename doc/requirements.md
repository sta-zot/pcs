Задача такая, надо написать небольшой веб сервер, который будет принимать запросы на получение конфигурационных файлов. Предполагаются следующие кейсы:
Если пришел запрос на получение конфигурационного файла для телефона, для котрого в бд есть конфигурация, минимум номер и пароль, отдаём файл.
> Необходимо определиться с настройками, минимальный набор SIP extension, password, sip_server_adress [ip], [hostname(имя телефона)],[display name]

Набор настроек должен быть универсальным и не иметь специфичных моделям настроек.

Механизм запроса на получение конфигурационного файла
1. Запрос на загрузку порсонифицированного файла с именем {MAC}.bot (например, abcd1234f1cb.boot)
> Boot-файл является необязательным элементом провижининга. Он определяет, какие файлы конфигурации cfg будут загружены определенными группами телефонов, и настраивает последовательность загрузки этих файлов. Сам boot-файл не содержит в себе непосредственно параметров конфигурации телефонов.
2. Запрос на загрузку общего файла с именем y000000.bot (например, y000000.boot)
> Конфигурационный файл содержит параметры конфигурации телефона, такие как SIP extension, password, sip_server_adress и другие.
> Два выше приведенных файла определяют список, какие cfg файлы конфигурации будут загружены

Если файл boot есть загружает файлы конфигурации по списку из файла *.boot.



3. Запрашивает персонифицированный файл конфигурации телефона {MAC}.cfg. Если  файл загружается применят настройки. Если файл не найден, переходит к шагу 4.
4. Запрашивает общий файл конфигурации y000000.cfg. 

Наша задача при получении запроса на загрузку файла конфигурации если её нет вернуть 404 и создать запись в таблице БД с информацией от телефоне, записать mac адрес(можно получить из имени файла), ip адрес, производителя, модель.  

сделать Web интерфейс где можно просматривать список телефонов и их конфигурации, а так же редактировать параметры и присваивать номера. Конфигурация считается доступной для загрузки, если заполнены минимальные поля (
account.1.enable = 1,
account.1.display_name = Иванов Иван,
account.1.label = Иванов,
account.1.auth_name = 1001
account.1.sip_user = 1001
account.1.sip_password = SuperSecretPassword123
account.1.sip_server_host = 192.168.1.10
account.1.sip_server_port = 5060
account.1.transport = 0
).
Пока только базывые настройки.
Возле кажного номера должен быть список номеров из которых можно выбрать для назначения. Список номеров и имён приложение должно получить из БД PBXсистемы(isabel).
## Структура
Получается у нас на начальном этапе должны быть
### На инфраструктурном уровне
####  Репозиторий для Extentions из PBX системы, в виде: Имени, номера и пароля. Берется из стандартной базы данных PBX системы.
####  Репозитория для Храниения таблицы телефонов. Модель, производитель, мак адрес.
```dbml
Table Phones {
  id int [primary key]
  
  created_at timestamp
  updated_at timestamp
}
```
  
####  Репозиторий для конфигураций. 
```dbml
Table Configurations {
  id int [primary key] 
  model string
  manufacturer string
  mac_address string
  supported bool
  sip_account_id int // display_name/label, auth_name sip_user, sip_password, 
  sip_server_host string
  sip_server_port int
  ip_address string
  created_at timestamp
  updated_at timestamp
  has_changed bool // Если конфигурация была изменена в БД                auto_provision.reboot_force = 1,
}
```
#### Генераторы конфигурационных файлов
для каждого производителя телефонов потребуется отдельный модуль.
Для удобства надо будет сделать фабрику для генераторов конфигурационных файлов.

###  На уровне приложения/сервиса
#### Создание конфигурационных файлов ввиде потока
Сервис должен будет создавать конфигурационные файлы для телефонов ввиде потока байт на основе данных из таблицы Configurations.
#### Управление конфигурациями
Редактирование конфигураций и управление их жизненным циклом. Получение и передача конфигураций ввиде структуры данных из репозитория конфигураций.
Телефоны Необходимо проверять является ли запросивщее устройство телефоном. либо из параметра User-Agent, либо API по прверке мак адресов. Если это телефон, записываем его в БД и прописываем глобальные значения, например адрес и порт сервера. Необходимо проверить поддерживается ли данная модель/производитель. Нужен внутренний API для проверки поддерживаемых моделей/производителей.
#### Управление номерами телефонов
Получение списка номеров телефонов, паролей, и имен из PBX

### На транспортном уровне 
#### Получение запросов на загрузку конфигурационных фалов 
При получении запроса на загрузку конфигурационного файла необходи определить есть ли конфигурация, если есть, то отдать её, если нет, вернуть 404 Not Found и записать информацию о отправителе запроса в базу данных.
> Предать в сервис управляющий телефонами

### Отображение списка телефонов
Выводим список всех телефонов, которые есть в базе данных с конфигурацией и признаком что конфигурация минимально полная. Надо отобразить Производителя, модель, ip адрес, mac адрес, присвоенный номер, Имя абонента, статус конфига[configured, unconfigured], кнопку редактировать.

### Редактирование конфигурации 
Может стоит склеить с  "Отображение списка телефонов"

Давай начнем с http хендлера, и зарегистрируем endpoint что бы получить информацию о телефоне, если файла для него нет, добавить в таблицу, если есть отдать файл, или точнее если сервис который управляет конфигами метод GetConfigFile() вернул поток байт который можно отдать, отдаём поток, если нет, то пишем в таблицу БД информацию о телефоне.
