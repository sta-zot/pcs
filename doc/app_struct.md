# Проектирование модуля автопровижининга IP-телефонов

## Назначение системы

Система предназначена для автоматической генерации конфигураций IP-телефонов (Yealink, Cisco SPA, Grandstream и др.) по запросу самого телефона.

Телефон определяется по MAC-адресу и модели (User-Agent/OUI), после чего система формирует полную конфигурацию и передаёт её генератору файлов.

Система **не управляет телефонами**, **не управляет SIP-номерами PBX** и **не является системой инвентаризации оборудования**.

Предметная область системы — **управление конфигурациями телефонов**.

# Домен

Для всех доменных моделей(entity и ObjectValue) необходимо использовать Сетеры и Гетеры.
Такой подход обеспечит простое изменение если понадобится логика при обработаке.

## Aggregate Root

### PhoneSettings

Главный объект предметной области.

Описывает полную конфигурацию одного телефона.

Содержит:

* идентификацию устройства;
* общие настройки;
* сетевые настройки;
* набор линий телефона.

```go
type Phone struct {
	mac         MACAddress
	vendor      Vendor
	model       Model


	Network     NetworkSettings
	General     GeneralSettings
	Lines       map[int]Line // Ключ — SlotID для быстрого доступа и сортировки
	hasChanges  bool      // Маркер наличия изменений
	lastFetched time.Time // Время последней отдачи конфига
	isComplite  bool
}
```
C учетом того что очень много дефолтных настроек, создание объекта лучше отдать спецализироанному модулю
что бы он проверил что пришедшие данные от телефона, производитель/модель поддерживается.
```go
// NewPhone - фабричный метод для создания нового устройства (по дефолту)
func NewPhone(mac MACAddress, vendor Vendor, model Model) *Phone {
	return &Phone{
		MAC:         mac,
		Vendor:      vendor,
		Model:       model,
		HasChanges:  true,
		Lines:       make(map[int]Line),
		LastFetched: time.Time{},
	}
}
```

## Entity

### LineSettings

Описывает конфигурацию одной линии телефона.
Жизненный цикл тесно связан с номером на АТС. 
Линия может находится не назначенной ни одной конфигурации телефона.

Линия определяется:

* номером (Extension);
* позицией на телефоне;
* SIP-настройками.
```go
type LineSettings struct {
    ID          int           // Идентификатор
	Slot        int          // Порядковый номер линии на аппарате (1, 2, 3...)
	IsActive    bool         // Включена ли линия
	SIPData     SIPSettings  // Данные регистрации посути это записи из таблицы sip БД asterisk
}

```

На уровне предметной области считается, что каждая линия содержит полный набор параметров, необходимых генератору.

## Value Objects

### SipSettings

Описание параметров SIP-регистрации.

Содержит:

* данные авторизации;
* параметры транспорта;
* параметры NAT;
* кодеки;
* таймеры;
* безопасность;
* прочие SIP-параметры.

```go
type SIPSettings struct {
	account     string // extension name / ID (например, "101")
	secret       string // Пароль из sip/pjsip settings
	displayname  string // Отображаемое имя (CallerID Name)
	serverHost   string // IP/Хост АТС
	serverPort   int    // 5060 / 5061
	transport    string // UDP, TCP, TLS
	dtmfMode     string // rfc2833, info, inband
	expireTime  int       // Тайм-аут регистрации
	updatedAt   time.Time // время последнего обновления
	hasChanged  bool      // для точечного обновления
}
````

---

### NetworkSettings

Настройки сети устройства.

```go
type NetworkSettings struct {

	StaticIP    net.IP
	SubnetMask  net.IPMask
	Gateway     net.IP
	PrimaryDNS  net.IP
	SecondaryDNS net.IP
```

# Domain Services

## Provisioning Service

Главный сервис предметной области.

Отвечает за получение готовой конфигурации телефона.

Не знает ничего о формате конфигурационных файлов.

Его задача — вернуть полностью сформированный объект `PhoneSettings`.

---

## Generator Factory

Выбирает генератор в зависимости от производителя и модели телефона.

Например:

```
YealinkGenerator

CiscoSPAGenerator

GrandstreamGenerator
```

Возвращает объект, реализующий общий интерфейс генерации конфигурации.

---

## Config Generator

Принимает `PhoneSettings`.

Возвращает поток (или байтовый массив) готового конфигурационного файла.

Генератор не знает:

* откуда получены параметры;
* как они были сформированы;
* где они хранятся.

---

# Repository Interfaces

На уровне домена существуют только интерфейсы.

Например:

## PhoneSettingsRepository

Отвечает за получение и сохранение конфигурации телефона.

Работает только с объектом `PhoneSettings`.

---

## LineRepository

Предоставляет список доступных линий (Extension) для назначения телефону.

Также позволяет получать информацию о конкретной линии.

На уровне домена не важно, откуда эти данные получены.

---

## DefaultsRepository

Предоставляет системные значения по умолчанию.

Источник данных не имеет значения.

---

## OUIRepository

Позволяет определить производителя и модель устройства по MAC/OUI и User-Agent.

---

# Infrastructure

Инфраструктурный слой отвечает за работу с внешними системами.

Например:

* наша MariaDB;
* база данных FreePBX;
* парсер OUI;
* файловая система;
* генераторы конфигураций;
* HTTP.

Именно здесь находятся:

* SQL;
* работа с таблицами `sip`;
* работа с `users`;
* загрузка YAML;
* чтение файлов.
